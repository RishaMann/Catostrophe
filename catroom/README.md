# Котику грустно — сцена 1 на Phaser

Перенос HTML-редактора в движок. Первая сцена с предметами, меню и иконками.

## Запуск

Нужен локальный сервер — с `file://` браузер не отдаст соседние скрипты.

```bash
cd catroom
python3 -m http.server 8080
# открыть http://localhost:8080
```

На Windows `python3`/`python` часто оказываются заглушками Windows Store,
которые ничего не запускают (тихо завершаются). Если так — тот же результат
даёт Node (обычно уже стоит для остального проекта):

```bash
npx serve -l 8080 catroom
```

Отладочные слои: `http://localhost:8080/?debug=1`

`iso.js` не импортирует ничего и не трогает DOM. Всё состояние передаётся аргументами. Это единственная гарантия, что редактор и движок не разойдутся в сортировке и легальности.

`RoomScene` грузит сцену по имени (`this.scene.start('room', {name: 'scene2'})`,
по умолчанию `'scene1'`) через `src/scenes/<имя>.json` родным
Phaser-загрузчиком (`this.load.json`). Механизм рассчитан на несколько сцен;
вторая сцена (коридор за дверью) пока не реализована.

## Сцена 1

`floor 8, tilt 0.5, zoom 1.0`, стены 3.4, дверь на левой стене, окно на правой.
26 зон, 18 предметов в стартовой раскладке, свободного пола 52 %, все предметы с подходом достижимы.

**Почему zoom 1.0, а не 1.35 со скриншота настроек.** При 135 % ближняя часть пола уходит ниже линии `MAXY = 700`, где живут панели, и весь передний ряд зон отбраковывается — из комнаты пропадают коробка, фикус, миски и лежанка. Экранный габарит комнаты от зума при этом почти не выигрывает: `F*TW` всегда равно `360*zoom`, то есть floor 8 zoom 1 кадрируется ровно так же, как дефолтные floor 6 zoom 1, просто клеток больше.

Пол шире кадра: по X он идёт от −90 до 630 при кадре 0…540. Ближние боковые углы обрезаны намеренно, зоны туда не раскладываются — за это отвечает `Lx` в `layoutBounds`.

## Что работает

- комната, одна стена без верхней линии обвода (см. ниже, зачем), проёмы
  двери и окна, сетка пола
- 18 предметов, сортировка по глубине: предмет ближе кота к зрителю его загораживает
- кот — спрайт (не блокаут), состояния idle / walk / sit / lie / eat / dig /
  jump, BFS-путь, ходьба на 8 экранных направлений; три персонажа
  (Рыжий/Сиамский/Лабрадор), переключаются кнопкой в нижнем правом меню, у
  каждого свой темп и частоты поведения (`Cats/*/config.json`)
- защитный респавн, если кот оказался вне проходимой области
- панели-трапеции в мёртвых углах кадра, сцену не перекрывают
- инвентарь открывается в правой трапеции, сцена не двигается
- перетаскивание предмета из инвентаря на легальную зону, откат при потере подхода
- перетаскивание уже стоящего предмета — только через захват-и-перенос (не
  тап): предмет остаётся на месте и видимым, пока его не отпустят на новой
  легальной зоне (переставить) или над правой панелью (вернуть в инвентарь)
- корм из «Запасов»: кот идёт к миске и ест
- debug-слои: проходимость, подписи зон, пустые зоны, кот вкл/выкл
- во время драга — причина отказа над призраком на нелегальной зоне, след
  подхода (где встанет кот) на легальной зоне для предметов с `touch`
- «Задания»/«Магазин» открывают панель-заглушку («Скоро») вместо того, чтобы
  ничего не делать
- мебель из линий (процедурные силуэты) или из спрайтов (вырезанные картинки)
  — тумблер «Мебель: линии/спрайты» в «Настройки» (см. ниже)

## Рендер: пул объектов, не перерисовка каждый кадр

Рендер разбит на три независимых слоя, а не один общий `Graphics`,
перерисовываемый целиком 60 раз в секунду:

- **Оболочка** (`gShell`: пол/стены/проёмы/debug-проходимость) —
  перерисовывается только когда `shellDirty` (взводится в `rebuild()` и при
  переключении «Проходимость» в настройках).
- **Предметы** (`itemGfx`: по `Graphics`+`Text` на занятую зону, включая
  потолочный подвес) — пересобирается только в `rebuild()`, глубина —
  `I.depth(zmap, zid)` через Phaser `.setDepth()`. Пул для меток тоже
  пересобирается точечно (`showLabels` дёргает `rebuildItemGfx()`).
- **Кот** (`gCat`) — единственное, что честно перерисовывается каждый кадр
  (маленькая фигура, не вся сцена), глубина — `cat.x + cat.y`, та же шкала,
  что у `I.depth()`, поэтому Phaser сам вставляет кота между предметами без
  ручного интерливинга по паре пикселей.

Подсветка пустых зон при драге (`zoneGfx`) рисуется только условно — пока
`showEmpty` включён или предмет в руке.

## Кот: спрайты по персонажам, не блокаут

Арт и поведение кота полностью данные, не код. `Cats/manifest.json`
перечисляет папки-персонажи; у каждой свой `config.json`:

```json
{
  "name": "Рыжий кот",
  "speed": 1.15,
  "behavior": { "idleMinS": 1.2, "wanderChance": 0.55, "sitChance": 0.30, ... },
  "sprites": { "walk": { "down": {"frames": [...], "flip": false}, ... }, "idle": "sit_front_a", ... }
}
```

`speed` и `behavior.*` управляют темпом и таймингами в
`tick()`/`idleCycle()`/`decideNext()`/`afterRest()`; `sprites.*` — какой файл
из `sprites/` показывать в каком состоянии (`walk` — циклы кадров по
направлениям, остальные — статичные позы). У сиамского дополнительно
`sprites.play` — покадровая анимация игрушкой (кадры `play_toy1_0..52`, взяты
из уже нарезанного арта в `public/art/cats/siamese/` в корне репозитория, куда
151 кадр `play_*` разложен ещё в `phaser-game/`); у рыжего такого нет — для
`jump` статичная поза с подскоком.

Загрузка каскадная (`RoomScene.preload`): манифест → конфиги персонажей →
только те PNG, что реально названы в их `sprites.*` — список кадров заранее
не известен движку, дозаписывается в очередь Phaser-загрузчика по мере того,
как приходят сами конфиги. `catFrameNames()` в `util.js` достаёт имена и из
плоского массива/строки, и из вложенной карты направлений `walk`.

**Ходьба — 8 экранных направлений.** `sprites.walk` — объект с ключами
`down/downleft/downright/left/right/up/upleft/upright`, у каждого
`{ frames: [...], flip }`. Экранное направление считает `catBehavior.tick()`
из вектора движения по той же формуле, что и проекция в `iso.js`
(`screenX=(x-y)*TW, screenY=(x+y)*TH`), кладёт в `cat.dir8`;
`catAppearance.updateCatVisual()` берёт по нему нужный набор кадров и флип
напрямую из конфига. На восемь направлений у персонажа реально только 4
разных набора кадров: `left`/`right` переиспользуют `downleft`/`downright` с
зеркалом, `upleft`/`upright` делят один набор так же — отдельного рисунка на
каждое из 8 направлений не нужно.

Также поддерживается плоский формат `sprites.walk` (массив кадров + флип по
`cat.dir`, `catAppearance.js` определяет форму по `Array.isArray`) — один цикл
ходьбы на оба горизонтальных зеркала, без полных 8 направлений.

Имена файлов кадров ходьбы не обязаны совпадать с тем, что на них изображено
(могут быть унаследованы из другого пайплайна) — при добавлении персонажа
направление каждого набора нужно проверять визуально, не по названию файла.

Превью в панели выбора персонажа тоже данные: `sprites.previewRotation` —
необязательный, формат `[[индекс_в_previewPoses, флаг_флипа], ...]`, тот же,
что и дефолт `ROTATION_ORDER` в `catAppearance.js` — задаёт свой порядок
«вращения» для персонажа (см. `Cats/Labra/config.json`).

## Мебель: линии или спрайты

Второй способ нарисовать предмет — не процедурный силуэт (`itemShapes.js`),
а вырезанная картинка. Переключается тумблером «Мебель: линии/спрайты» в
«Настройки» (`this.furnitureSprites`, `drawSettings`/`onDown`), применяется
и к floor-мебели (`drawFloorItemInto`), и к настенным предметам
(`drawWallItemInto`, сейчас только `curtain`) — по умолчанию выключен, старое
поведение (линии) не меняется, пока не включат явно.

`Furniture/manifest.json` — какие id каталога (`data.js`) вообще имеют
картинку и в каких состояниях:

```json
{ "box": { "new": "box/new.png", "afterGag": "box/afterGag.png" }, ... }
```

Сами PNG (`Furniture/<id>/<state>.png`) вырезаны из
`Documentation/References/furniture.png` по альфа-каналу (без ручной обводки)
и грузятся в движок той же каскадной схемой, что и кадры кота
(`game.js: createStep2LoadImages`, обычные `Image()`, не `this.load.image`, —
см. комментарий там же про то, почему). `room/furnitureSprites.js`
(`FURN_SPRITES`) — тонкий реестр поверх манифеста: `has`/`pickState`/
`textureKey`, ничего больше.

**state — задел на будущее, не готовая механика.** У предмета может быть
несколько картинок сразу (сейчас вырезаны `box.new`/`box.afterGag` — коробка
закрыта/распотрошена, и `curtain.new`/`curtain.afterGag` — шторы подхвачены/
задёрнуты), но переключение состояния по игровому событию (гэг кота) нигде не
вызывается: `FURN_SPRITES.pickState(iid, wanted)` всегда получает `wanted =
pos.state` из `st.floor[iid]`, которое никто пока не пишет, поэтому везде
показывается `'new'`. Когда появятся анимация гэга/состояние после гэга/
анимация кота у конкретного предмета — их картинки/кадры лягут в тот же
`Furniture/<id>/` и тот же манифест, без переделки реестра.

**Разворот при перестановке.** Процедурный силуэт умеет поворачиваться на 90°
(`frame()`/`orientation()` в `itemShapes.js`) — картинка так не может, поэтому
спрайт вместо поворота зеркалится по той же стороне, что решает ориентацию
силуэта (`cx <= cy` — ближе к левой стене, иначе к дальней, см.
`I.floorOrient`/`floorSnap`): `entry.img.setFlipX(cx > cy)`.

**Перекрытие кота не завязано на способ отрисовки.** Глубина спрайта — та же
`I.floorDepth(pos)` (=`pos.x+pos.y`), что и у процедурного силуэта, и та же
шкала, что у кота (`cat.x+cat.y`) — Phaser сам сортирует `Image` и `Graphics`
кота по общему `.depth`, свойство «мебель ближе кота её загораживает»
работает одинаково в обоих режимах без отдельного кода.

## Стена без верхней линии

`RoomScene.wallFace()` рисует заливку стены и только 3 ребра (пол, ближний и
дальний вертикальные края) — верхнее ребро сознательно не рисуется: у обеих
задних стен оно визуально пересекало бы высокие предметы (шкаф, стеллаж) —
они полупрозрачные, и линия силуэта комнаты у потолка просвечивала бы сквозь
них.

## Чего пока нет

- геометрия сцены не редактируется в игре — это работа редактора уровней
- реальное наполнение «Заданий»/«Магазина» — сейчас просто открывающаяся панель
- переключение состояния предмета по игровому событию (гэг кота) — манифест и
  реестр это уже умеют (см. «Мебель: линии или спрайты»), но ничего пока не
  меняет `st.floor[iid].state`; следы, пары предметов
- вторая зона за дверью, задник за окном
- арт предметов и комнаты — по умолчанию процедурный блокаут; часть каталога
  (см. `Furniture/manifest.json`) уже можно показать вырезанными картинками
  через тумблер «Мебель: спрайты», остальное так и рисуется линиями, пока для
  него не вырежут картинку; у кота — настоящие спрайты всегда (см. «Кот:
  спрайты по персонажам»)

## Известные особенности

- в комнате есть карман из 3 навигационных ячеек между шкафом и дверью — кот туда не попадает и не пытается; на раскладку не влияет, но при перестановке мебели стоит поглядывать на счётчик `pockets`
- иконки и предметы — блокаут; сортировка длинных предметов держится на правиле «крупная мебель стоит вдоль стены», при переносе на спрайты понадобится секционная отрисовка или ручной `sortAnchor`
