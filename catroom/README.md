# Котику грустно — сцена 1 на Phaser

Перенос HTML-редактора в движок. Первая сцена с предметами, меню и иконками.

## Запуск

Нужен локальный сервер — с `file://` браузер не отдаст соседние скрипты.

```bash
cd catroom
python3 -m http.server 8080
# открыть http://localhost:8080
```

На Windows `python3`/`python` часто оказываются заглушками Windows Store,
которые ничего не запускают (тихо завершаются). Если так — тот же результат
даёт Node (обычно уже стоит для остального проекта):

```bash
npx serve -l 8080 catroom
```

Отладочные слои: `http://localhost:8080/?debug=1`

## Файлы

| Файл | Что внутри | Общий с редактором |
|---|---|---|
| `src/iso.js` | проекция, зоны, габариты, глубина, проходимость, A* | **да, буквально тот же файл** |
| `src/data.js` | каталог предметов и запасов (общий для всех сцен) | да |
| `src/scenes/scene1.json` | раскладка сцены 1 (params/door/win/light/cat/place) | да |
| `src/icons.js` | векторные иконки предметов на Graphics | да |
| `src/game.js` | рендер, кот, панели, инвентарь, ввод | нет, только движок |
| `Cats/manifest.json` | список папок-персонажей | нет |
| `Cats/<Имя>/config.json` | скорость, частоты поведения, какой файл из `sprites/` за что отвечает | нет |
| `Cats/<Имя>/sprites/*.png` | кадры персонажа (из `public/art/cats/` в корне репозитория) | нет |

`iso.js` не импортирует ничего и не трогает DOM. Всё состояние передаётся аргументами. Это единственная гарантия, что редактор и движок не разойдутся в сортировке и легальности.

Сцена больше не зашита в `data.js` — `RoomScene` грузит её по имени
(`this.scene.start('room', {name: 'scene2'})`, по умолчанию `'scene1'`)
через `src/scenes/<имя>.json` родным Phaser-загрузчиком (`this.load.json`).
Это задел под вторую сцену (коридор за дверью) — самой второй сцены пока нет,
только механизм.

## Сцена 1

`floor 8, tilt 0.5, zoom 1.0`, стены 3.4, дверь на левой стене, окно на правой.
26 зон, 18 предметов в стартовой раскладке, свободного пола 52 %, все предметы с подходом достижимы.

**Почему zoom 1.0, а не 1.35 со скриншота настроек.** При 135 % ближняя часть пола уходит ниже линии `MAXY = 700`, где живут панели, и весь передний ряд зон отбраковывается — из комнаты пропадают коробка, фикус, миски и лежанка. Экранный габарит комнаты от зума при этом почти не выигрывает: `F*TW` всегда равно `360*zoom`, то есть floor 8 zoom 1 кадрируется ровно так же, как дефолтные floor 6 zoom 1, просто клеток больше.

Пол шире кадра: по X он идёт от −90 до 630 при кадре 0…540. Ближние боковые углы обрезаны намеренно, зоны туда не раскладываются — за это отвечает `Lx` в `layoutBounds`.

## Что работает

- комната, одна стена без верхней линии обвода (см. ниже, зачем), проёмы
  двери и окна, сетка пола
- 18 предметов, сортировка по глубине: предмет ближе кота к зрителю его загораживает
- кот — спрайт (не блокаут), состояния idle / walk / sit / lie / eat / dig /
  jump, BFS-путь; два персонажа (Рыжий/Сиамский), переключаются кнопкой в
  нижнем правом меню, у каждого свой темп и частоты поведения (`Cats/*/config.json`)
- защитный респавн, если кот оказался вне проходимой области
- панели-трапеции в мёртвых углах кадра, сцену не перекрывают
- инвентарь открывается в правой трапеции, сцена не двигается
- перетаскивание предмета из инвентаря на легальную зону, откат при потере подхода
- перетаскивание уже стоящего предмета — только через захват-и-перенос (не
  тап): предмет остаётся на месте и видимым, пока его не отпустят на новой
  легальной зоне (переставить) или над правой панелью (вернуть в инвентарь)
- корм из «Запасов»: кот идёт к миске и ест
- debug-слои: проходимость, подписи зон, пустые зоны, кот вкл/выкл
- во время драга — причина отказа над призраком на нелегальной зоне, след
  подхода (где встанет кот) на легальной зоне для предметов с `touch`
- «Задания»/«Магазин» открывают панель-заглушку («Скоро») вместо того, чтобы
  ничего не делать

## Рендер: пул объектов, не перерисовка каждый кадр

Комната больше не один общий `Graphics`, перерисовываемый целиком 60 раз в
секунду. Три независимых слоя:

- **Оболочка** (`gShell`: пол/стены/проёмы/debug-проходимость) —
  перерисовывается только когда `shellDirty` (взводится в `rebuild()` и при
  переключении «Проходимость» в настройках).
- **Предметы** (`itemGfx`: по `Graphics`+`Text` на занятую зону, включая
  потолочный подвес) — пересобирается только в `rebuild()`, глубина —
  `I.depth(zmap, zid)` через Phaser `.setDepth()`. Пул для меток тоже
  пересобирается точечно (`showLabels` дёргает `rebuildItemGfx()`).
- **Кот** (`gCat`) — единственное, что честно перерисовывается каждый кадр
  (маленькая фигура, не вся сцена), глубина — `cat.x + cat.y`, та же шкала,
  что у `I.depth()`, поэтому Phaser сам вставляет кота между предметами без
  ручного интерливинга по паре пикселей.

Подсветка пустых зон при драге (`zoneGfx`) осталась условной (только пока
`showEmpty` или предмет в руке) — это и раньше было дёшево, не часть
проблемы с полной перерисовкой.

## Кот: спрайты по персонажам, не блокаут

Арт и поведение кота полностью данные, не код. `Cats/manifest.json`
перечисляет папки-персонажи; у каждой свой `config.json`:

```json
{
  "name": "Рыжий кот",
  "speed": 1.15,
  "behavior": { "idleMinS": 1.2, "wanderChance": 0.55, "sitChance": 0.30, ... },
  "sprites": { "walk": ["walk_frontleft_0", ...], "idle": "sit_front_a", ... }
}
```

`speed` и `behavior.*` — это ровно то, что раньше было захардкожено в
`tick()`/`idleCycle()`/`decideNext()`/`afterRest()`; `sprites.*` — какой файл
из `sprites/` показывать в каком состоянии (`walk` — цикл кадров, остальные —
статичные позы). У сиамского дополнительно `sprites.play` — покадровая
анимация игрушкой (кадры `play_toy1_0..52`, взяты из уже нарезанного арта в
`public/art/cats/siamese/` в корне репозитория, куда 151 кадр `play_*`
разложен ещё в `phaser-game/`); у рыжего такого нет — для `jump` просто
статичная поза с подскоком, как раньше у блокаута.

Загрузка каскадная (`RoomScene.preload`): манифест → конфиги персонажей →
только те PNG, что реально названы в их `sprites.*` — список кадров заранее
не известен движку, дозаписывается в очередь Phaser-загрузчика по мере того,
как приходят сами конфиги.

Кадры `sprites.walk` в исходном арте «смотрят» влево на экране без флипа —
кнопка переключения персонажа и флип по `cat.dir` это уже учитывают
(`flip = cat.dir > 0`), проверено визуально на обоих персонажах в обе
стороны. Если заводить нового персонажа с другим художественным
направлением взгляда «в ноль» — это тоже придётся перепроверить глазами, тут
общего правила из `phaser-game` (там была честная 6-направленная таблица)
не хватает — у catroom всего одно зеркалирование влево/вправо, не 6 гексовых
направлений.

## Стена без верхней линии

У обеих задних стен раньше рисовался полный периметр (`poly(...)` со
stroke по всем 4 рёбрам) — верхняя линия (силуэт комнаты у потолка) визуально
пересекала высокие предметы (шкаф, стеллаж): они полупрозрачные, линия
позади них всё равно просвечивала. `RoomScene.wallFace()` рисует заливку
стены и только 3 ребра (пол, ближний и дальний вертикальные края) — верхнее
сознательно пропущено.

## Чего пока нет

- геометрия сцены не редактируется в игре — это работа редактора уровней
- реальное наполнение «Заданий»/«Магазина» — сейчас просто открывающаяся панель
- состояния предметов «после кота», следы, пары предметов
- вторая зона за дверью, задник за окном
- арт предметов и комнаты — по-прежнему процедурный блокаут, ассетов нет;
  только у кота теперь настоящие спрайты (см. «Кот: спрайты по персонажам»)

## Известные особенности

- в комнате есть карман из 3 навигационных ячеек между шкафом и дверью — кот туда не попадает и не пытается; на раскладку не влияет, но при перестановке мебели стоит поглядывать на счётчик `pockets`
- иконки и предметы — блокаут; сортировка длинных предметов держится на правиле «крупная мебель стоит вдоль стены», при переносе на спрайты понадобится секционная отрисовка или ручной `sortAnchor`
