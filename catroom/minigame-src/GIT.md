# Работа с двух компьютеров

Проект живёт на GitHub. Дома и на работе — одна и та же папка,
синхронизируется тремя командами.

## Один раз дома

```bash
cd C:\Projects\cat-new\game

git init
git add .
git commit -m "Скелет игры"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/cat.git
git push -u origin main
```

Репозиторий сначала создать на github.com кнопкой **New**, без README и .gitignore —
они уже есть в проекте.

## Один раз на работе

```bash
git clone https://github.com/ТВОЙ_ЛОГИН/cat.git
cd cat
npm install
npm run dev
```

## Каждый раз, когда сел за компьютер

```bash
git pull
```

Забираешь то, что сделал на другом компьютере. **Делать всегда до начала работы.**

## Каждый раз, когда что-то заработало

```bash
git add .
git commit -m "Коротко: что сделал"
git push
```

Не «когда закончу модуль», а каждый раз, когда игра запустилась и не сломалась.
Это единственная страховка, и она бесплатная.

## Если что-то сломалось и непонятно почему

```bash
git checkout .
```

Откатывает всё несохранённое к последнему коммиту. Проще начать заново
от рабочего состояния, чем разбирать завал.

## Чего в репозитории быть не должно

Файл `.gitignore` уже настроен и не пускает туда:

- `node_modules/` — сто мегабайт библиотек, восстанавливаются командой `npm install`
- `dist/` — собранная версия, пересобирается
- `.env` — **токен бота и ключи платежей.** Их в репозиторий класть нельзя никогда,
  особенно если репозиторий публичный

## Если забыл сделать push перед уходом

Ничего страшного: работа осталась на том компьютере. Просто на другом
не начинай править те же файлы, иначе при следующем `git pull`
придётся разбирать конфликт.
