# Промпт для разработки: двойная сетка комнаты

**Проект:** «Котику грустно» / Cat Was Here
**Этап:** 1 — сетка, навигация по полу, перекрытие, debug
**Стек:** Phaser 3, TypeScript, мобильный портрет, ретро-пиксель
**Версия промпта:** 1.0 · 03.09.2026

> **Как пользоваться.** Этот файл целиком отдаётся разработчику или кодовому агенту как задание. Он самодостаточен: все числа, формулы и критерии приёмки внутри. Разделы 3–5 содержат математику, в которой легко ошибиться — их нельзя переписывать «по смыслу», только копировать.

---

## 1. Что делаем

Комната в изометрии 2:1 с двумя задними стенками. **Две независимые сетки над одной и той же комнатой:**

| Сетка | Форма клетки | Для чего | Видна игроку |
|---|---|---|---|
| **Размещение** | квадрат 32×32 | мебель, слоты, стены, потолок | только в режиме расстановки |
| **Навигация** | шестиугольник | ходьба кота по полу | **никогда** |

Кот ходит **только по свободному полу**. Стены и мебель — препятствия. Предмет, стоящий ближе к зрителю, чем кот, загораживает кота.

Из скоупа этого этапа **исключены**: ходьба по верхним поверхностям мебели, лазание по вертикальным граням, состояния «внутри» и «под», зоны за дверью и окном, потолок. Но архитектура не должна их закрывать — см. §7.5.

## 2. Три уровня, которые нельзя смешивать

```
Уровень 3  игровая логика: A*, карта интереса, ходьба, перекрытие
           ↓ работает ТОЛЬКО через интерфейс решётки
Уровень 2  решётки: SquareGrid (размещение) + HexLattice (навигация)
           ↓ обе выражают себя в мировых координатах
Уровень 1  проекция мир → экран (зафиксирована навсегда)
```

**Жёсткое правило.** Код уровня 3 не имеет права предполагать четыре соседа, целочисленные `x, y` или квадратную клетку. Только `neighbors()`, `worldToCell()`, `cellToWorld()`. Проверка на код-ревью: если в A* встречается `x+1` или `Math.abs(dx)+Math.abs(dy)` — правило нарушено.

## 3. Уровень 1 — проекция

Мировые координаты: `wx` вправо-вглубь, `wy` влево-вглубь, `wz` вверх. Единица — 1/32 клетки.

```ts
// мир → экран
export const projX = (wx: number, wy: number) => (wx - wy) / 2;
export const projY = (wx: number, wy: number, wz = 0) => (wx + wy) / 4 - wz / 2;

// экран → плоскость пола (wz = 0)
export const unproject = (sx: number, sy: number) => ({
  wx: sx + 2 * sy,
  wy: 2 * sy - sx,
});
```

Обе функции принимают координаты **относительно origin комнаты**. Origin комнаты — это мировая точка `(0,0,0)`, то есть дальний угол пола. Смещение origin в экране хранит камера, а не эти функции.

Проекция не меняется никогда и не зависит от решётки. Следствие: `wz` ортогонален полу, поэтому высоты, стены и матрица прыжка не зависят от формы клетки пола.

## 4. Уровень 2A — квадратная сетка размещения

| Параметр | Значение |
|---|---|
| Сторона клетки `S` | 32 мировые единицы |
| Индекс клетки | `(i, j)`, `i ∈ [0, W)`, `j ∈ [0, D)` |
| Центр клетки | `wx = S*i + S/2`, `wy = S*j + S/2` |
| Экранный ромб | 32 × 16 px |
| Размер комнаты по умолчанию | `W = 8`, `D = 8`, `wallHeight = 6` |

Сюда ложатся: футпринты мебели `[w, d]`, высота в клетках, слоты, сетки двух стен `(u, z)`, потолок. Размер комнаты параметрический — все три числа приходят из `RoomSpec`, нигде не хардкодятся.

Мебель описывается так:

```ts
interface FurnitureInstance {
  id: string;
  cell: [number, number];        // origin, квадратные координаты
  footprint: [number, number];   // [w, d] в клетках
  height: number;                // в клетках
  blocksFloor: boolean;          // true → пол под предметом непроходим
  sortAnchor?: [number, number]; // см. §8.3
}
```

## 5. Уровень 2B — гексагональная сетка навигации

**Решётка определяется в экранных координатах, а не в мировых.** Это сделано осознанно: правильный шестиугольник после изометрической проекции превращается в неправильный, с шестью разными наклонами рёбер, и перестаёт быть пиксель-перфектным. Экранный изо-гекс собран из чистых наклонов 2:1 и горизонталей.

### 5.1 Геометрия клетки

Вершины относительно центра, в экранных пикселях:

```
(-24, 0) · (-8, -8) · (8, -8) · (24, 0) · (8, 8) · (-8, 8)
```

Габарит — **48 × 16 px**. Шесть рёбер: две горизонтали по 16 px и четыре наклона 16×8. Ни одного «кривого» пикселя.

### 5.2 Раскладка

| Параметр | Значение |
|---|---|
| Шаг колонок | 32 px по X |
| Шаг строк | 16 px по Y |
| Нечётные колонки | смещены на **+8 px по Y** (odd-q offset) |
| Площадь клетки | 512 px² = ровно две квадратные клетки |

```ts
// центр гекса (c, r) в экранных координатах относительно origin комнаты
export const hexCenter = (c: number, r: number) => ({
  sx: 32 * c,
  sy: 16 * r + ((c & 1) ? 8 : 0),
});
```

### 5.3 Шесть соседей (odd-q offset)

Копировать буквально. Это то место, где ошибаются всегда.

```ts
export function hexNeighbors(c: number, r: number): [number, number][] {
  const odd = c & 1;
  return [
    [c,     r - 1],
    [c,     r + 1],
    [c + 1, odd ? r     : r - 1],
    [c + 1, odd ? r + 1 : r    ],
    [c - 1, odd ? r     : r - 1],
    [c - 1, odd ? r + 1 : r    ],
  ];
}
```

Все шесть рёбер равны по длине в мировой метрике. Стоимость шага одинакова для всех шести — никаких корней из двух и никаких поправок на диагональ. Это и есть главный выигрыш гекса.

### 5.4 Генерация решётки под комнату

```ts
function buildHexLattice(W: number, D: number): HexCell[] {
  const cells: HexCell[] = [];
  // габарит пола в экранных координатах
  const corners = [[0,0], [S*W,0], [S*W,S*D], [0,S*D]];
  const xs = corners.map(([a,b]) => projX(a,b));
  const ys = corners.map(([a,b]) => projY(a,b));
  const c0 = Math.floor(Math.min(...xs) / 32) - 1, c1 = Math.ceil(Math.max(...xs) / 32) + 1;
  const r0 = Math.floor(Math.min(...ys) / 16) - 1, r1 = Math.ceil(Math.max(...ys) / 16) + 1;

  for (let c = c0; c <= c1; c++) for (let r = r0; r <= r1; r++) {
    const { sx, sy } = hexCenter(c, r);
    const { wx, wy } = unproject(sx, sy);
    // клетка входит в решётку, только если её ЦЕНТР внутри пола
    if (wx < 0 || wy < 0 || wx > S * W || wy > S * D) continue;
    cells.push({ c, r, sx, sy, wx, wy });
  }
  return cells;
}
```

Критерий включения — центр внутри пола. Граница комнаты получается слегка зубчатой; это нормально и невидимо, потому что решётка не рисуется.

## 6. Мост между сетками

Единственная точка связи двух сеток. Всё остальное о них не знает.

```ts
function markBlocked(hex: HexCell[], furniture: FurnitureInstance[]) {
  for (const h of hex) {
    const i = Math.floor(h.wx / S);
    const j = Math.floor(h.wy / S);
    h.blocked = furniture.some(f =>
      f.blocksFloor &&
      i >= f.cell[0] && i < f.cell[0] + f.footprint[0] &&
      j >= f.cell[1] && j < f.cell[1] + f.footprint[1]
    );
  }
}
```

**Правило разрешения конфликта:** гекс блокируется, если его **центр** попадает в занятую квадратную клетку. Не «пересекается», а именно центр — иначе мебель отгрызает вокруг себя лишнюю полосу и проходы исчезают.

Пересборка блокировок — только по событиям: постановка, снятие, смена состояния предмета «после кота», открытие зоны. Не в `update()`.

## 7. Уровень 3 — навигация

### 7.1 Что проходимо

| Что | Проходимо |
|---|---|
| Свободный пол | да |
| Пол под мебелью с `blocksFloor: true` | нет |
| Плоскости стен | нет — стены не входят в решётку вообще |
| За границей пола | нет — таких клеток нет в решётке |

Стены не нуждаются в отдельной проверке: генератор §5.4 их просто не создаёт.

### 7.2 A*

Обычный A* по графу гексов. Эвристика — мировое расстояние между центрами:

```ts
const dist = (a: HexCell, b: HexCell) => Math.hypot(a.wx - b.wx, a.wy - b.wy);
```

Стоимость всех рёбер одинакова. Приоритетная очередь — бинарная куча; сортировка массива на каждой итерации на 30–40 клетках работает, но её надо заменить до релиза.

Если путь не найден — кот не идёт и играет анимацию «дёрнул ухом». Никогда не телепортируется и никогда не идёт частичным путём в стену.

### 7.3 Движение

- Кот интерполируется между центрами гексов, позиция — float. Снапа к решётке в визуале нет.
- Внутри клетки добавляется фиксированное псевдослучайное смещение до ±3 px (сид от `c, r`), чтобы траектория не выглядела машинной. Смещение постоянно для клетки, а не дрожит.
- Скорость: Батон 34 px/с, Шило 52 px/с (экранные пиксели, до масштабирования).

### 7.4 Ракурсы: шесть направлений на четыре спрайта

**Отдельная задача, о которой легко забыть.** У кота два ракурса плюс отзеркаливание — это 4 экранных направления. Гекс даёт 6. Нужно отображение:

```ts
// четыре спрайтовых направления в экранных углах
const SPRITE_DIRS = [ /* front-right */ 26.57, /* front-left */ 153.43,
                      /* back-left */ -153.43, /* back-right */ -26.57 ];
```

- направление шага берётся в **экранных** координатах, не мировых;
- выбирается ближайшее по углу спрайтовое направление;
- два гекс-направления `(0, ±16)` (строго вглубь и строго к зрителю) лежат точно между двумя спрайтовыми — в этом случае **сохраняется предыдущий ракурс**, чтобы не было дребезга;
- смена ракурса не чаще одного раза в 150 мс.

### 7.5 Задел на будущее, который надо заложить сейчас

Решётка навигации создаётся **не для комнаты, а для навигационного патча**. На этом этапе патч один — пол. Интерфейс:

```ts
interface NavPatch {
  id: string;
  z: number;                 // высота патча в клетках
  bounds: WorldRect;         // прямоугольник в мировых координатах
  lattice: HexCell[];
  links: PatchLink[];        // пусто на этом этапе
}
```

Верх дивана, полка и подоконник позже становятся такими же патчами со своей гекс-решёткой, а `links` — рёбрами прыжка и лазания. Если сейчас захардкодить «решётка = пол», это придётся переписывать целиком.

## 8. Перекрытие: предмет впереди загораживает кота

### 8.1 Принцип

Художник Painter's algorithm по одному числу. Всё, что рисуется в комнате, лежит в одном списке и сортируется перед отрисовкой.

```ts
depth = (wx + wy) * 8 + wz * 2 + facetBias
```

`wx, wy, wz` — мировые координаты **точки сортировки** объекта. Больше `depth` = ближе к зрителю = рисуется позже = загораживает.

`facetBias`: декаль −4, стена −2, предмет пола 0, кот +1, подвес 0.

Кот получает `+1`, чтобы при равном `wx + wy` он оказывался поверх предмета — стоя ровно на линии с предметом, кот должен быть видим, а не съеден.

### 8.2 Точка сортировки

| Объект | Точка сортировки |
|---|---|
| Кот | мировой центр текущего гекса `(wx, wy)` |
| Предмет 1×1 | ближний к зрителю угол клетки: `(S*(i+1), S*(j+1))` |
| Предмет N×M | ближний к зрителю угол футпринта, либо `sortAnchor` |
| Декаль | своя мировая точка |

### 8.3 Длинные предметы — известная ловушка

Диван на трёх клетках нельзя сортировать одним числом: кот может быть одновременно за одним его концом и перед другим. Три варианта, в порядке возрастания цены:

1. **`sortAnchor` вручную + правило «крупная мебель стоит вдоль стены».** Достаточно для этого этапа. За предметом у стены кот почти не бывает, а если бывает — он в состоянии «за мебелью» и всё равно должен быть перекрыт.
2. **Секционная отрисовка.** Спрайт нарезан в атласе на изо-колонки по одной квадратной клетке, каждая колонка сортируется своим `depth`. Правильно всегда, но требует дисциплины в арте.
3. **Топологическая сортировка** попарных отношений «перед/за». Общее решение, для 18 предметов избыточно.

**Для этого этапа реализуем вариант 1**, но `depth` вынести в отдельную функцию с одним входом, чтобы вариант 2 подключался без переписывания рендера.

### 8.4 Проверочные конфигурации

Сцена для ручного теста, все четыре случая обязаны работать:

1. Кот подходит к торшеру с дальней стороны → торшер **перед** котом, кот частично скрыт.
2. Кот подходит с ближней стороны → кот **перед** торшером, торшер целиком виден.
3. Кот идёт вдоль дивана слева направо → перекрытие меняется в момент перехода за линию `sortAnchor`, без мерцания.
4. Кот стоит ровно на одной линии с предметом → кот **поверх**.

## 9. Три режима отображения

### 9.1 Обычный (по умолчанию)

**На полу не рисуется ничего.** Ни гексов, ни квадратов, ни подсветки клеток, ни маркеров слотов, ни зон, ни точек интереса, ни целевой клетки после тапа.

Единственная допустимая обратная связь на тап — короткая круговая волна 200 мс в точке касания, **не привязанная к форме клетки** и не выровненная по сетке. Если она выглядит как подсветка клетки — убрать.

Свободные слоты имеют собственный «арт отсутствия» (светлый прямоугольник от снятой картины, вытертый след от мебели) — но это часть текстуры комнаты, а не оверлей, и он не подсвечивается.

### 9.2 Режим расстановки

Включается при входе из магазина или при взятии перемещаемого предмета. Только здесь появляются оверлеи, и только квадратные:

- легальные слоты под взятый предмет — подсветка;
- нелегальные — не подсвечиваются вовсе;
- слот, ломающий связность пола, — красная рамка;
- призрак предмета снапится к ближайшему легальному слоту в радиусе полуклетки.

**Гексагональная решётка не показывается даже здесь.** Игрок расставляет мебель по квадратам и о гексах не знает никогда.

При выходе из режима все оверлеи гарантированно снимаются — один общий контейнер `placementOverlay`, который целиком скрывается. Не по одному объекту.

### 9.3 Debug

Отдельная сцена-оверлей `DebugGridScene`, отключаемая целиком. Включение: `?debug=1` в URL или четыре тапа по счётчику валюты. В продакшн-сборке вырезается по флагу бандлера.

Переключатели независимые, состояние в `localStorage`:

| Клавиша | Слой |
|---|---|
| `1` | квадратная сетка размещения + индексы `(i, j)` |
| `2` | гексагональная решётка навигации |
| `3` | заблокированные гексы (заливка) |
| `4` | рёбра графа навигации |
| `5` | текущий путь кота + номера шагов |
| `6` | точки и значения `depth` у всех объектов |
| `7` | футпринты и `sortAnchor` мебели |
| `8` | кадр камеры и безопасная зона UI |
| `0` | всё выключить |

Плюс текстовая панель: FPS, число гексов, число свободных, длина пути, число изломов пути, режим отображения.

**Изломы пути** — метрика качества: считать смены направления на маршруте. Она нужна, чтобы численно сравнивать гекс с квадратом, если решение придётся защищать.

## 10. Интерфейсы

```ts
interface RoomSpec {
  size: [number, number];        // [W, D] в квадратных клетках
  wallHeight: number;            // в клетках
  navLattice: 'hex' | 'square';  // 'hex' по умолчанию, 'square' для сравнения в debug
}

interface HexCell {
  c: number; r: number;          // индекс в решётке
  sx: number; sy: number;        // центр в экранных координатах
  wx: number; wy: number;        // центр в мировых координатах
  blocked: boolean;
  nb: HexCell[];                 // проходимые соседи, кэш
}

interface Lattice {
  cells: HexCell[];
  at(c: number, r: number): HexCell | undefined;
  fromWorld(wx: number, wy: number): HexCell | undefined;
  fromScreen(sx: number, sy: number): HexCell | undefined;
  rebuildBlocked(furniture: FurnitureInstance[]): void;
  findPath(from: HexCell, to: HexCell): HexCell[];
}
```

`navLattice: 'square'` держим не ради релиза, а чтобы в debug можно было переключить решётку и сравнить путь. Обе реализации за одним интерфейсом — это и есть проверка, что правило §2 не нарушено.

## 12. Порядок реализации

Каждый шаг проверяем глазами до перехода к следующему.

1. `projection.ts` + пустая комната: пол, две стены, сетка стен. **Проверка:** ромб пола симметричен, стены сходятся в дальнем углу без щели в один пиксель.
2. Квадратная сетка + мебель кубами по `RoomSpec`. **Проверка:** меняем `W` и `D` слайдером — мебель переезжает по якорным правилам, ничего не вылезает за пол.
3. Гекс-решётка + debug-слой `2`. **Проверка:** гексы плотно замощают пол без щелей и наложений; на границе — зубчатый край, это нормально.
4. Мост §6 + debug-слой `3`. **Проверка:** заблокированные гексы точно под мебелью, ни одного лишнего вокруг.
5. A* + debug-слои `4` и `5`. **Проверка:** путь огибает диван, не пролезает через угол, не находится сквозь стену.
6. Ходьба кота + ракурсы §7.4. **Проверка:** кот не дребезжит ракурсом при движении строго вглубь.
7. Сортировка по глубине + четыре конфигурации §8.4.
8. Режимы §9. **Проверка:** в обычном режиме на полу пусто; после выхода из расстановки не осталось ни одного оверлея.

## 13. Критерии приёмки

- [ ] Размер комнаты меняется в `RoomSpec` без правок кода; обе решётки пересобираются
- [ ] Кот ходит только по свободному полу; ни одного случая прохода сквозь мебель или стену
- [ ] Мебель, стоящая ближе к зрителю, загораживает кота; дальняя — нет
- [ ] Все четыре конфигурации §8.4 отработаны, мерцания на границе нет
- [ ] Тап в недостижимую точку не вызывает движения и не ломает состояние
- [ ] Тап в клетку под мебелью не вызывает движения
- [ ] В обычном режиме на полу нет ни одного оверлея, ни одной подсветки, ни одной сетки
- [ ] После выхода из режима расстановки оверлеев не осталось
- [ ] Гексагональная решётка не видна игроку ни в одном режиме, кроме debug
- [ ] Debug-слои включаются независимо, состояние переживает перезагрузку
- [ ] Debug вырезается из продакшн-бандла
- [ ] Пересборка блокировок не вызывается в `update()`
- [ ] 60 fps на среднем Android при 8×8 и 6 предметах
- [ ] В `nav/astar.ts` нет ни одного упоминания `i`, `j`, `x+1` или манхэттенского расстояния

## 14. Чего делать не надо

- **Не рисовать гексы игроку.** Ни намёком, ни в подсветке цели, ни в тени под котом.
- **Не смешивать сетки.** Мебель никогда не встаёт на гекс, кот никогда не ходит по квадрату.
- **Не блокировать гекс по пересечению с мебелью** — только по попаданию центра. Иначе проходы схлопываются.
- **Не строить 3D-воксельный грид.** Пол — плоскость, высота живёт в патчах.
- **Не пересобирать решётку в кадре.** Только по событиям.
- **Не сортировать объекты по `y` спрайта.** Только по `depthOf()`.
- **Не сглаживать путь A*** на этом этапе: сначала надо увидеть сырой путь, иначе непонятно, что именно сглаживание чинит.
- **Не хардкодить `W = 8`.** Нигде.
